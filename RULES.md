# Rules

Rules to follow before giving any answer while building this project. More may be added over time.

1. **Never change `GOALS.md` or `POINTS_TO_REMEMBER.md` unless explicitly told to.** I can read them, quote them, and suggest what should be added or checked off — but I don't edit either file on my own initiative. Only do it when you say so directly (e.g. "mark X as done," "add this to Points to Remember").

2. **Flag testing opportunities instead of silently acting on them.** When we reach a piece of code that could use a test case, or a point that deserves its own testing stage, say so explicitly — ping you about it — rather than quietly adding tests on my own or quietly skipping them.

3. **File-by-file build process.** Before adding any project file: show its full content, briefly explain in very easy English what that file is doing, and ask if there are any questions about it. Only write/stage the file once told to — and commit it to GitHub only when explicitly told "commit this file as final."
