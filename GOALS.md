# Goals — Hotel Base-Camp Comparator

Everything below is copied from `STUDENT_GUIDE.md`. This is the checklist we build against.

Status legend: `[ ]` Not started · `[~]` In progress · `[x]` Completed (only marked once there's real evidence, noted in `POINTS_TO_REMEMBER.md`)

## How to Approach the Problem with AI

- [x] Start with problem understanding: Use AI to break down requirements and identify key components
- [x] Write a plan before coding: Record 3–5 ordered implementation steps, important dependencies or checkpoints, and how you will verify each stage
- [x] Design before coding: Work with AI to choose a simple architecture and familiar technologies that fit within one day
- [x] Use iterative prompting: Refine AI responses with specific constraints and context
- [x] Verify and understand: Always read through generated code and ask AI to explain complex parts
- [x] Test continuously: Generate test cases and sample data as you build
- [x] Track plan changes: Note where implementation differed from the original plan and why
- [x] Document your process: Save key prompts, decisions, and iterations for the interview discussion

## Required Deliverables

### 1. Implementation Plan

- [x] Ordered steps: Describe the 3–5 connected stages you intended to follow
- [x] Checkpoints: State what working evidence or test would complete each stage
- [x] Changes from plan: Briefly note anything you reordered, simplified, deferred, or corrected and why
- [x] Presentation ready: Be prepared to walk the interviewer through the plan before demonstrating the solution

### 2. Working Solution

- [ ] Functional core features: Focus on getting the main functionality working
- [ ] Running instructions: Clear steps to run your application
- [ ] Sample data: Include realistic test data to demonstrate your solution

### 3. AI Interaction Documentation

- [ ] Prompt history: Save screenshots or copy-paste of key prompts you used with specific constraints and context
- [ ] Iteration examples: Show how you refined prompts to improve results (start broad, then add specific requirements)
- [ ] Problem-solving examples: Document how AI helped you debug or overcome challenges

### 4. Design Summary

- [ ] Architecture decisions: Why you chose specific components/technologies (prioritize simplicity and familiar tools)
- [ ] AI influence: How AI recommendations shaped your design
- [ ] Trade-offs: What you prioritized and what you deferred

### 5. Test Evidence

- [ ] Test plan: How the application was tested
- [ ] Edge case handling: Evidence you considered error scenarios

### 6. Development Environment Ready

- [ ] Live modification capability: Keep your development environment ready for one small change and a possible second; each will be scoped to no more than 10 minutes
- [ ] Quick startup: Ensure you can run your application and make modifications efficiently
- [ ] AI tools accessible: Have your preferred AI assistant ready for use during the interview
- [ ] Requirement translation: Be ready to convert a brief user request into a precise AI-assistant instruction and explain what you accepted, changed, or rejected from the response
- [ ] Technology familiarity: Use technologies you can explain and debug confidently
